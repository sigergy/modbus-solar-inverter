Nombres de entidad: corto en su dispositivo

Patrón de §5.4 de la spec, decidido el 5 de octubre de 2026. Valores de ejemplo. Borrador: nada está implementado.

Regla: la entidad no repite su dispositivo. Ejemplo: Batería · Estado de carga.

ámbar nombre que solo, sin dispositivo, no dice de qué es

Cómo compone HA el nombre (has_entity_name, adapters/inbound/entities/base.py:16): nombre visible = «dispositivo» + «entidad». Unas vistas muestran solo la entidad; otras, el nombre completo. Qué vista muestra cuál depende de la versión de HA: está marcado como pendiente de verificar en la VM al final.

El nombre del dispositivo lleva el Device ID de la entry detrás (spec §5.6): «Batería 0». De ahí sale el entity_id: sensor.bateria_0_potencia. Un segundo equipo con ID 1 da «Batería 1» y sensor.bateria_1_potencia, sin sufijo _2. Una entry creada antes de v2 no tiene Device ID: su dispositivo se llama «Batería», sin número.

Si la plantilla usa solo el nombre de la entidad, se pierde el contexto: «Estado de carga ha bajado del 20 %» se entiende, pero «Potencia supera 3 kW» no.

4. Selector de entidades (automatizaciones, tarjetas)

El usuario escribe para buscar. Se ve el nombre completo y el entity_id. Busca «potencia»:

Batería 0 Potenciasensor.bateria_0_potencia
Batería 1 Potenciasensor.bateria_1_potencia
Red 0 Potenciasensor.red_0_potencia
Consumo 0 Potenciasensor.consumo_0_potencia
Campo solar 0 Potencia FV1sensor.campo_solar_0_potencia_fv1

«Batería 1» es la batería de un segundo inversor, con Device ID 1. Los bits del BMS son binary_sensor: binary_sensor.bateria_0_alarma_tension_alta.

El entity_id se genera una vez al crear la entidad (spec §5.4). Solo cambia si el usuario cambia el Device ID en «Reconfigurar» (spec §4.5). El idioma del entity_id está por verificar.
